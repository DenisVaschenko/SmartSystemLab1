# ADR-0002. Доставка команд через MQTT, файлів через HTTPS

## Статус
Прийнято, 20.11.2026.

## Контекст
FR-04 вимагає адресувати обрані зони, FR-08 — збирати результати. На 12 зон припадає до 720 КБ аудіоданих одного типового повідомлення. Повторне з’єднання може спричинити повторну доставку команди.

## Варіанти
1. Опитувати сервер через HTTP. Інтервал опитування входить у бюджет затримки навіть за порожньої черги.
2. Передавати команди й аудіофайли через брокер. Повторне отримання великих файлів навантажує той самий канал, що й короткі команди.
3. Використати MQTT для маніфестів і звітів, HTTPS для завантаження файлів за ключем.

## Рішення
Обрано третій варіант. Контролер підписується на тему своєї зони. Маніфест містить ID, версію, пріоритет, час виконання, строк чинності, текст і ключ файла. Доставка QoS 1 допускає дублікати; контролер звіряє пару (ID, версія) з локальним журналом. Після перепідключення він спершу отримує актуальний знімок чинних завдань, потім обробляє накопичені зміни за версіями. Звіт про вихід відрізняється від мережевого підтвердження доставки.

## Наслідки
Файл із відомою сумою можна повторно використати. Інженер обслуговує брокер і файловий API. Доступ до тем обмежено ідентичністю контролера, а API перевіряє роль користувача перед публікацією. Поновлення лише мережевого з’єднання ще не підтверджує успішне озвучення.
